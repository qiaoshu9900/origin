I. Background and Problem
In our daily work, we often carry out relatively large changes. In such large changes, the most important part is the final checkout — the final verification. Typically, we need to compare a large amount of raw output from many devices.

In the past, after obtaining the outputs from many devices, we spent a lot of time comparing them because the raw output contains a huge amount of information. At the same time, human errors were common. For example, when comparing the outputs of two machines, many differences were highlighted in red, and the path changes were not clearly shown by ordinary tools, making it difficult to quickly locate the issues.

II. Solution 1: A Script Written with AI
To solve this problem, I used AI to build a tool specifically designed to handle raw checkout comparisons for a large number of devices. Initially, the tool was created for SCMR removal (a specific change). Today, I will demonstrate it using real SMR removal checkout files.

When using a tool like kdiff to check a file, the differences appear messy.

When using my script to check the same file, the results are much clearer.

This script automatically does the following:

Aligns each route's different paths for comparison;

Clearly shows which routes existed before the change and which exist after;

For each route, if only attributes have changed, it lists exactly which attributes changed;

Generates a separate report for each device;

Besides CSV or HTML output, it also provides a CSV file for those who need to do further development or additional comparisons.

In short, this is a tool dedicated to comparing routing checkout outputs.

III. Enhanced Functionality in the HTML File
When processing the HTML file, the tool enriches the data by checking existing databases (including QIP subnet and other databases) to determine the source of each route. This allows us to quickly identify which routes have disappeared or suddenly appeared, and where they came from.

If some routes are not found in our databases (for example, external routes), the tool can use AS_PATH to analyze their most likely location, helping with root cause analysis.

V. Generality and Extensibility
It is worth noting that the current Agent and prompt are generic — there is nothing specifically written for SMR. Therefore, if we need to perform a particular type of check, we can easily add our expectations. For example, in an SMR change, we might expect ASPA to decrease. Such expectations can be written in, and the AI will analyze the results accordingly.
